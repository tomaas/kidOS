1. **BLOCKER — Boot validation still prevents DB-only image/TTS configuration.** The design says key validation moves to point-of-use, but Chunk 1 only explicitly removes the `ANTHROPIC_API_KEY` requirement. Today [src/env.ts](/home/user/Developer/kidOS/src/env.ts:120) remains boot-fatal when `IMAGE_ENABLED=true` lacks an env Gemini key, and likewise for ElevenLabs. That fails if the key exists only in SQLite or if DB settings disable a feature that env enables. Remove all movable provider/key validation from boot; retain only infrastructure validation such as `DATABASE_URL`.

2. **BLOCKER — “Effacer” does not actually clear a secret under DB-wins/env-fallback.** Chunk 3 says explicit clear deletes the row, which merely reactivates the env secret. The UI would claim the key was erased while it remains effective. Represent three distinct operations: keep current, store a new value, and explicitly override with an empty DB value. “Reset to deployment default” should separately delete the row. Cover all three in `test:settings`.

3. **SHOULD-FIX — The cache is unnecessary complexity for this SQLite deployment and has an invalidation race.** With roughly fourteen rows in a local SQLite database, reading configuration once per server operation is the safer 80/20 design. A cached promise can be invalidated while its initial read is in flight and then repopulate stale data unless guarded by a generation counter. Invalidation is also process-local; a second Nitro process/container remains stale for the TTL. Either remove the cache initially, or specify generation-based invalidation and explicitly document cross-process convergence as TTL-bound rather than immediate.

4. **SHOULD-FIX — One logical operation can observe multiple configuration generations.** The proposed consumer rewiring independently calls `getAppConfig()` in gates, providers, and logging. A settings save between those reads can produce combinations such as “image enabled” from one snapshot and key/model/resolution from another. Read one immutable snapshot at the server-function boundary and pass the relevant provider configuration downward. This also fixes `logTextGen()` in [src/server/providers/text/dynamic.ts](/home/user/Developer/kidOS/src/server/providers/text/dynamic.ts:63), which is synchronous and cannot simply replace `serverEnv.storyModel` with an awaited lookup.

5. **SHOULD-FIX — Runtime branding risks using UI language for story-language content.** The existing comment in [src/config/app.ts](/home/user/Developer/kidOS/src/config/app.ts:36) says the print colophon and fallback title should follow `stories.lang`, not the current UI locale. Chunk 4 proposes threading root-loader branding into [src/components/printable-story.tsx](/home/user/Developer/kidOS/src/components/printable-story.tsx:15), which would make an English story printed while the UI is French receive French derived branding. Pass `childName` plus overrides and derive branding using the story’s frozen language; similarly use the requested story language for the fallback title in [src/server/dynamic-functions.ts](/home/user/Developer/kidOS/src/server/dynamic-functions.ts:231).

6. **SHOULD-FIX — Chunk 1’s `AppConfig` contract contradicts the later branding work.** It says `AppConfig` has the same shape as `serverEnv`, but its canonical keys include four branding values absent from [src/env.ts](/home/user/Developer/kidOS/src/env.ts:46). Define the complete typed shape in Chunk 1, including branding, or deliberately split `ProviderConfig` and `BrandingConfig`. Otherwise Chunk 4 must redesign the supposedly frozen choke-point.

7. **SHOULD-FIX — Shipping inert branding controls is a poor chunk boundary.** Chunk 3 lets parents save branding fields that “only take effect in C4.” A completed intermediate commit would present controls that visibly do nothing. Move branding inputs to Chunk 4, or combine Chunks 3 and 4. Every independently mergeable chunk should leave the UI truthful.

8. **SHOULD-FIX — Secret non-disclosure needs boundary tests, not only helper tests and manual DevTools inspection.** A masking-unit test cannot prove a `createServerFn` response never serializes `AppConfig`. Add an integration/golden test invoking the read/save server-function boundary and recursively scanning the serialized response for planted secret values. Also add a static import-graph assertion that client components cannot import the full secret-bearing configuration module.

9. **SHOULD-FIX — Cache invalidation must include every writer, including the existing locale writer.** [src/server/settings-functions.ts](/home/user/Developer/kidOS/src/server/settings-functions.ts:48) already writes `app_settings`. If the new service reads all rows, `saveUiLocaleFn` must invalidate it too. Prefer central `setSetting/deleteSetting` write helpers so a future writer cannot omit invalidation.

10. **SHOULD-FIX — Root-router caching is a second cache not addressed by the service TTL.** The root route has `staleTime: Infinity` in [src/app/__root.tsx](/home/user/Developer/kidOS/src/app/__root.tsx:84). The current tab can explicitly call `router.invalidate()`, but another open tab may retain old branding/locale/flags indefinitely until reload. Document reload as the consistency boundary, or add a lightweight revalidation strategy; the server TTL alone does not solve client router staleness.

11. **SHOULD-FIX — First-run/concurrent saves need an atomic patch contract.** A whole-form read-modify-write can lose edits when two tabs save different sections, especially with “empty secret means keep.” Make the request a field-level patch and execute all upserts/deletes in one SQLite transaction; invalidate only after commit. Add concurrent disjoint-update and failed-transaction tests.

12. **SHOULD-FIX — Point-of-use failure should distinguish missing configuration from provider failure.** [src/server/providers/text/dynamic.ts](/home/user/Developer/kidOS/src/server/providers/text/dynamic.ts:810) currently throws a missing-key error that is absorbed into the generic child-facing soft failure. That is correct for the child, but the parent settings page needs a deterministic configuration status/code. Test that no provider network call occurs when the key is absent and that the child still receives calm wording.

13. **NIT — The import-graph claim is directionally right but overstated.** Lazy-importing `~/server/db` prevents DB bootstrap when coherence goldens import `dynamic.ts`, and that should be pinned. However those tests already set `SKIP_ENV_VALIDATION=1`, and merely keeping prompt builders byte-identical does not prove the full import graph is harmless. The proposed “no DB file created” subprocess test is the meaningful contract; also assert `app-config.ts` has no static import of `~/server/db` or a module that re-exports it.

14. **NIT — Tolerant boolean parsing can silently convert corruption into an unintended override.** The current `bool()` behavior in [src/env.ts](/home/user/Developer/kidOS/src/env.ts:9) treats every non-`true` value as false. For a malformed DB row, safer normalization is “invalid means fallback,” not “invalid means disabled.” Test missing, valid true/false, empty explicit override where applicable, and garbage separately.

15. **NIT — The chunk file list understates the provider refactor.** `dynamic.ts` has synchronous helpers such as cost logging, `getTtsProvider()` changes signature, and image configuration is consumed at both server-function and provider layers. Treat Chunk 2 as an API-signature refactor, not a mechanical six-file replacement, and require type-check plus focused provider tests before the full golden lattice.

16. **PRAISE — Keeping `BLOB_READ_WRITE_TOKEN` in env preserves the existing SSRF boundary.** [src/server/providers/media-store.ts](/home/user/Developer/kidOS/src/server/providers/media-store.ts:145) derives the exact Blob host when possible, and [allowedStoredMediaUrl](/home/user/Developer/kidOS/src/server/providers/media-store.ts:203) rejects non-HTTPS and foreign hosts. Leaving backend selection outside parent-editable settings avoids both storage-mode foot-guns and allowlist/cache incoherence. Keep `test:media` unchanged and mandatory.

17. **PRAISE — Extending `app_settings` with no boot seed is the right basic storage model.** The existing table at [src/server/db/schema.ts](/home/user/Developer/kidOS/src/server/db/schema.ts:368) is adequate, avoids a needless migration, and pure fallback preserves env rotation semantics—provided explicit empty overrides and reset-to-env are modeled separately.

18. **PRAISE — The plan respects the CALM constraint and the golden-test lattice.** Neutral parent-only configuration states, server-returned codes, child-facing soft failure, and explicit preservation of prompt/schema byte pins align well with [CLAUDE.md](/home/user/Developer/kidOS/CLAUDE.md). The proposed `test:settings` is a good addition, especially if it is expanded with the boundary, concurrency, and explicit-clear cases above.

**Verdict:** The core direction—typed server choke-point, SQLite-backed overrides, env fallback without boot seeding, runtime branding, and keeping media backend configuration in env—is sound. I would not begin the provider/UI chunks until the boot-validation contradiction, explicit-secret-clear semantics, configuration snapshot strategy, and story-language branding behavior are resolved. For this single-process local-SQLite product, the strongest simplification is to omit caching initially; it removes most invalidation and race concerns at negligible cost while preserving a clean path to add measured caching later.
