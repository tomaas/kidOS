precedence in C6, snapshot rule in C3, import-graph rule in C2 are
contracts).

## Chunk 1 — Settings service core (`app-config.ts`) + golden

**Scope**: the server-only settings choke-point. No consumer changes.
- New `src/server/app-config.ts`: canonical key list (design C1), the FULL
  typed shape `AppConfig = { provider: ProviderConfig; branding:
  BrandingConfig }` (frozen NOW — Chunk 4 adds consumers, never reshapes),
  `getAppConfig()` with precedence DB>env>default, one-query fresh read
  (**NO cache, no invalidation machinery**), never-throw (env-only on DB
  failure + log), **invalid-means-fallback** bool/enum parsing for DB rows,
  `hintFor(secret)` masking helper.
- Central `setSetting`/`deleteSetting` write helpers (validation +
  normalization live here); support the FOUR secret operations: keep (no
  write) / set / explicit empty override (`""` row masks env) / reset-to-
  default (delete row). Rewire the existing `saveUiLocaleFn` through them.
- HARD RULE: no top-level import of `~/server/db` (direct or via re-export) —
  lazy dynamic import inside the read/write functions.
- `src/env.ts`: keep shape; demote to fallback provider; boot validation
  becomes INFRA-ONLY per design C4 (remove ANTHROPIC + Gemini + ElevenLabs
  key checks AND the image/TTS gating; DATABASE_URL checks stay fatal).
  Update `test:db` pins in the SAME chunk.
- New `test:settings` script in package.json + `src/server/__tests__/
  app-config.golden.ts`: precedence matrix, FOUR secret ops, bool/enum cases
  pinned separately (missing / true / false / empty override / garbage),
  masking, never-throw, frozen key list, transactional field-level patch
  (concurrent disjoint updates + failed-transaction rollback), boundary
  secret-scan (serialize server-fn responses, scan for planted secrets),
  **subprocess** import-graph proof (import app-config.ts in a blank tmp dir
  → no db file created; static no-`~/server/db`-import assertion).

**Files**: src/server/app-config.ts (new), src/env.ts,
src/server/settings-functions.ts (saveUiLocaleFn rewire), package.json,
src/server/__tests__/app-config.golden.ts (new),
src/server/db/__tests__/local-sqlite.golden.ts (validation pins).
**QA**: `bun run test:settings test:db check-types lint`; full `bun run test`
still green; `bun run dev` boots WITHOUT any .env.local key, including with
IMAGE_ENABLED=true and no GEMINI_API_KEY (former boot-fatal case).

## Chunk 2 — Snapshot threading through providers & server functions
(AMENDED: treat as an API-SIGNATURE REFACTOR, not a find-replace)

**Scope**: each server-function handler takes ONE `getAppConfig()` snapshot
at its boundary and threads it (or the relevant sub-config) down.
- `server/functions.ts` + `server/dynamic-functions.ts`: snapshot up front;
  gates (imageEnabled, ttsEnabled), model/resolution resolution, defaultLang
  all read the SAME snapshot; pass config into providers.
- `text/dynamic.ts`: `generateBeat`/`generateStoryArc` gain a config param;
  sync `logTextGen()` receives the model from the threaded snapshot (stays
  sync). `image/nanobanana.ts`: `generateImage` gains config. `tts/index.ts`:
  `getTtsProvider(config)`; `tts/elevenlabs.ts` gets the key threaded.
- `getPublicFlags(config)` derives from the snapshot (keep env.ts db-free).
- Missing key at point of use: NO provider network call; child gets the
  existing typed soft-failure; server fns surface a deterministic
  config-status CODE (distinct from provider-failure codes) for /parents.
- `media-store.ts`, `db/index.ts`: UNCHANGED (blob token + DATA_DIR stay env).

**Files**: the 6 files above (+ any golden harness signature fallout).
**QA — gated order**: (1) `bun run check-types` FIRST (signature refactor),
(2) focused provider goldens (test:golden, test:coherence — prompt byte-pins
MUST NOT move), (3) full `bun run test` + lint. Manual: key only in DB (no
env) → story generates; key only in env → still generates; IMAGE_ENABLED
flipped in DB shows/hides the illustration slot on reload without rebuild;
no outbound provider call when unconfigured (server log).

## Chunk 3 — /parents/reglages UI + server fns

**Scope**: parent-facing page + save/read server functions. AMENDED: NO
branding inputs here (they ship with Chunk 4 — no inert controls in any
mergeable state).
- Extend `src/server/settings-functions.ts` (or sibling module):
  `getAppSettingsStatusFn` (non-secret values + `{configured, hint}` for
  secrets — NEVER the secret — + per-feature config-status codes),
  `saveAppSettingsFn`: **field-level PATCH**, zod-validated, executed as ONE
  SQLite transaction through the central `setSetting`/`deleteSetting`
  helpers; secrets follow the FOUR operations (keep / set / explicit empty
  override / reset-to-default); returns CODES.
- New route `src/app/parents/reglages.tsx` + a card/link on /parents index.
  Card grammar of the existing 🌍 card; sections Histoires / Images / Voix
  (secret fields expose "Effacer" = empty override and "Revenir au réglage
  du déploiement" = delete row, with the "par défaut (env)" badge).
- Saving tab calls `router.invalidate()`; other tabs converge on reload
  (documented consistency boundary — no new revalidation machinery).
- i18n: `parents.reglages.*` keys in BOTH `messages/fr.ts` and
  `messages/en.ts` (parity + calm-wording scans enforce); aria via
  `formatMessage`.
- Calm: neutral "non configurée" states, no red, no urgency, no validation
  nagging.

**Files**: src/server/settings-functions.ts, src/app/parents/reglages.tsx
(new), src/app/parents/index.tsx, src/lib/i18n/messages/{fr,en}.ts.
**QA**: test:i18n + test:routes + test:settings green; browse-QA: save
round-trip, secret masked after reload (response payload inspected — no
secret in any response), the four secret operations behave distinctly
(empty override ≠ reset-to-default with an env key present), toggle image →
reload → slot state changes; two-tab disjoint saves don't clobber.

## Chunk 4 — Branding goes runtime (VITE_* → DB) + branding UI inputs

**Scope**: design C1 branding keys + design section (3)-trace, AND the
"Prénom & nom de l'atelier" section of /parents/reglages (moved here from
Chunk 3 so controls take effect the moment they ship).
- `src/config/app.ts`: keep `buildBranding` composition but source
  childName/overrides from a server read with `import.meta.env.VITE_*` /
  `process.env.VITE_*` as fallback. Client consumers stop importing the
  module-level consts.
- Root loader (`__root.tsx`): extend the existing `getUiLocaleFn` call to one
  fn returning `{locale, branding, childName}`; provide via context next to
  `LocaleProvider`. Head tags read loader data. `staleTime: Infinity` stays;
  reload = the client consistency boundary (documented).
- Rework consumers: `portrait.tsx` (childName + branding from context);
  **STORY-LANG branding** (codex #5): `printable-story.tsx` colophon and the
  `dynamic-functions.ts` fallback story title receive childName + overrides
  and derive via `brandingFor(story.lang)` — never the UI locale.
- UI: branding inputs on /parents/reglages with live derived preview via the
  pure `buildBranding`; i18n keys added in BOTH catalogs (coordinate with
  Chunk 3's catalog edits if parallel).
- `buildBranding` and `matchesChildName` stay byte-identical (goldens).
- Dockerfile/compose: mark `ARG VITE_*` legacy-optional (keep as fallback).

**Files**: src/config/app.ts, src/app/__root.tsx,
src/components/bureau/portrait.tsx, src/components/printable-story.tsx,

## FINAL QA CHECKER BRIEFING (end-to-end, after all chunks merge)

Environment: fresh worktree, `bun install`. Use /browse (CONTAINER=1, own
BROWSE_STATE_FILE/PORT per the orchestrator skill) against `bun run dev`.

1. **Cold boot, zero config**: empty DATA_DIR, NO .env.local secrets →
   `bun run dev` boots (no boot-fatal key error — including
   IMAGE_ENABLED=true with no GEMINI_API_KEY). `/` renders; /parents
   renders with a calm "non configurée" status (config-status code, not a
   provider error); story creation returns the calm soft-failure with NO
   outbound provider call, never a crash.
2. **Settings page**: /parents/reglages loads in fr AND en (switch 🌍);
   every label localized; no calm-constraint violations (no scores/urgency).
3. **Save round-trip**: enter a fake then the real ANTHROPIC key; reload —
   field shows masked hint only. Assert via devtools/network that NO response
   payload ever contains the stored secret.
4. **DB-stored key drives generation + four secret ops**: with the key ONLY
   in DB (env unset), create a story → beats generate. "Revenir au réglage
   du déploiement" (delete row) with env fallback set → still generates
   (precedence proof). "Effacer" (explicit empty override) with an env key
   present → feature reads as UNCONFIGURED (env masked — the honest clear).
5. **Hot toggles, no rebuild, no stale mix**: flip image/TTS toggles in UI →
   reload child pages → illustration slot & "Écouter" button appear/
   disappear on the NEXT operation (no cache). Change IMAGE_MODEL/RESOLUTION
   → next image call uses them (server log). Second open tab converges on
   its next reload (documented boundary — not a bug).
6. **Branding runtime + story language**: set child name in UI → tab title,
   portrait label, booklet footer (print preview) update on reload. Print an
   ENGLISH story under a FRENCH UI → colophon stays English
   (`brandingFor(story.lang)`). Unset everything + VITE_CHILD_NAME env →
   legacy derivation intact.
7. **Resilience**: hand-edit an app_settings row to garbage (bad enum, bad
   bool) → app renders, value falls back to env/default
   (invalid-means-FALLBACK, never invalid-means-disabled), no error
   surfaces. Two-tab disjoint saves: both edits survive.
8. **Suites**: `bun run check-types && bun run lint && bun run test` all
   green — verify test:settings exists and runs in the `test` chain; verify
   the prompt byte-pins (test:golden/test:coherence) did NOT change.
9. **Docker path** (if the box allows): `bun run deploy` with a minimal
   `.env.production` (no keys) → container healthy on :3009, configure via
   UI, generate a story; `docker compose restart` → settings persist (volume).
10. Report: pass/fail per item, screenshots for 2/5/6, any calm-constraint
    concern flagged verbatim.
